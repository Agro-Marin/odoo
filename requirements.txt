# What belongs where:
#   requirements.txt         the framework (`odoo/`) plus the always-loaded
#                            addons — what every server process imports no
#                            matter which modules are installed
#   requirements-addons.txt  dependencies reached from one bundled addon, owned
#                            by the module that imports them
#   requirements-test.txt    needed to RUN the suites, not to run the server
#   requirements-dev.txt     linters, type checkers, native-extension build tools
#
# All pins are at the current release. Notes on the four whose version is
# load-bearing.
#
# cryptography and pyopenssl move as one unit — each pyopenssl release narrows
# the cryptography range it accepts:
#   25.3.0 -> <47      26.0.0 -> <47          26.1.0 -> <48
#   26.2.0 -> <49      26.3.0 -> >=49,<50     26.4.0 -> >=49,<51
#
# cbor2 6.1.4
#   Surface: cbor2.loads / cbor2.dumps, from the vendored webauthn helpers only,
#     both under a bare `except Exception`.
#   No advisory against 5.9.0 or 6.1.4. 5.9.0 stays a safe floor: it fixes
#     GHSA-3c37-wwvx-h642 (HIGH, uncontrolled recursion in cbor2.loads), which
#     _vendor/webauthn/helpers/parse_cbor.py reaches with attacker-supplied
#     bytes from an unauthenticated endpoint. 5.8.0 does not.
#   6.1.4 vs 5.9.0, 18 cases: encodings byte-identical, decodes identical —
#     truncated, empty, trailing garbage, duplicate keys, indefinite lengths,
#     half floats, bignum tags, 100k nested arrays (CBORDecodeError on both).
#   6.x renames the C extension `_cbor2` -> `cbor2._cbor2`. Not imported here.
#
# cryptography 50.0.0
#   Clears the four advisories the 46.x line carried: GHSA-537c-gmf6-5ccf
#     (HIGH, vulnerable OpenSSL in the wheels) at 48.0.1; GHSA-jwv3-5hgf-82ww
#     (HIGH, exponential path-building) and GHSA-m2h6-j472-rp4c (MODERATE,
#     wildcard escape from permittedSubtrees) at 49.0.0; GHSA-g6cj-pr64-35w5
#     (HIGH, Bleichenbacher oracle, PKCS#7 EnvelopedData decryption) at 50.0.0.
#   50.0.0 vs 46.0.7, all 54 call sites across odoo/enterprise/agromarin,
#     DeprecationWarning raised as an error: identical. Still present, and the
#     three most exposed to the jump: hazmat.decrepit TripleDES
#     (payment_redsys), hazmat.backends.default_backend() (agromarin
#     documents_l10n_mx_edi), pkcs7.PKCS7SignatureBuilder (enterprise
#     l10n_ar_edi).
#   For 51.x: the PKCS#7 advisory covers EnvelopedData DECRYPTION, which
#     nothing here performs (l10n_ar_edi only signs). iot_drivers/tools/
#     certificate.py reads the not_valid_after PROPERTY, deprecated since 42 for
#     not_valid_after_utc, still only deprecated on 50.0.0 — the one call site a
#     removal takes out.
#
# pyopenssl 26.4.0
#   Required by cryptography 50.0.0 (26.3.0+ needs cryptography>=49).
#   GHSA-5pwr-322w-8jr4 (HIGH, DTLS cookie callback buffer overflow) and
#     GHSA-vp96-hxj8-p424 (LOW, TLS bypass via unhandled servername-callback
#     exception) are fixed in 26.0.0; 25.3.0 carried both. No advisory affects
#     26.x.
#   26.4.0 vs 25.3.0, identical across: OpenSSL.crypto.Error, OpenSSL.SSL.Error,
#     VERIFY_PEER / VERIFY_NONE / VERIFY_FAIL_IF_NO_PEER_CERT,
#     X509.from_cryptography, X509Store, X509StoreContext(Error),
#     crypto.load_certificate / load_privatekey / FILETYPE_PEM (enterprise
#     l10n_nl_reports), urllib3.contrib.pyopenssl's PyOpenSSLContext /
#     get_subj_alt_name / inject_into_urllib3, and _ctx.set_verify() /
#     use_certificate() / add_extra_chain_cert() / use_privatekey() /
#     check_privatekey() / get_cert_store().add_cert() on in-memory material.
#   Load-bearing, not legacy: base/ir_mail_server.py feeds database-stored
#     certificate material to a PyOpenSSLContext via _ctx.use_certificate() /
#     use_privatekey(). stdlib ssl cannot — load_cert_chain() takes file paths
#     only, so dropping pyopenssl means writing private keys to disk. Also
#     reached by auth_passkey's vendored webauthn (chain validation),
#     certificate/, l10n_it_edi and enterprise l10n_nl_reports.
#   Broken on every version in range, so not a regression:
#     l10n_it_edi/tools/remove_signature.py reaches OpenSSL._util.lib for
#     PKCS7_verify. cryptography no longer compiles the PKCS7_* CFFI bindings
#     and pyopenssl no longer exports load_pkcs7_data; its suppress(Exception)
#     hides the AttributeError. Separate defect.
#
# reportlab 5.0.0
#   No advisory against 4.4.10 or 5.0.0.
#   The hold required visual comparison, so output was compared, not the API:
#     same documents generated on both versions, rasterised at 150 dpi, diffed
#     pixel by pixel. 4 PDFs identical (max per-channel delta 0), 3 barcode PNGs
#     byte-identical, stringWidth (built-in and embedded TTF) and
#     Paragraph.wrap exact.
#   Paths covered: tools/pdf canvas + colors + ImageReader + units;
#     libs/barcode createBarcodeDrawing + .asString("png"); snailmail platypus
#     Frame / KeepInFrame / Paragraph; l10n_ch graphics.shapes Drawing / Image
#     via renderPDF; enterprise sign TTFont + stringWidth + Paragraph + canvas.
#   5.0.0 declares charset-normalizer. It adds no package — requests and
#     pdfminer.six already pull it — and does not reverse the chardet decision
#     in requirements-addons.txt; base_import imports chardet by name.
#   rlPyCairo is now only reportlab's `pycairo` extra, so the direct pin below
#     is what installs it. .asString("png") needs a renderPM backend and there
#     is no other source on Linux.
