# Runtime dependencies of the Odoo server itself.
#
# What belongs where:
#   requirements.txt         the framework (`odoo/`) plus the always-loaded
#                            addons — what every server process imports no
#                            matter which modules are installed
#   requirements-addons.txt  dependencies reached from one bundled addon, owned
#                            by the module that imports them
#   requirements-test.txt    needed to RUN the suites, not to run the server
#   requirements-dev.txt     linters, type checkers, native-extension build tools
#
# The admission rule for this file: the framework imports it, or an addon that
# is always present (`base`, `web`) imports it *unguarded*. A package reached
# only from a specific module belongs in requirements-addons.txt and is declared
# in that module's __manifest__.py `external_dependencies`, so a missing one
# reports as a named MissingDependencyError on the install path instead of an
# ImportError at import time — coding_guidelines.rst §1.2.
#
#     pip install -r requirements.txt                          # server only
#     pip install -r requirements.txt -r requirements-addons.txt   # + bundled addons
#
# Four pins are deliberately held below their latest release. Each needs work
# these lines cannot carry on their own, so bump them one at a time, not in a
# sweep:
#   cbor2 (6.x)         major; auth_passkey's vendored webauthn decodes with it
#   cryptography (50.x) four majors across 54 call sites
#   pyopenssl (26.x)    major. It is load-bearing, not legacy cruft: mail
#                       servers store certificate material in the database and
#                       base/ir_mail_server.py feeds it to a PyOpenSSLContext
#                       via _ctx.use_certificate()/use_privatekey(), which
#                       stdlib ssl cannot do — load_cert_chain() takes file
#                       paths only, so dropping it would mean writing private
#                       keys to disk. Also reached by auth_passkey's vendored
#                       webauthn (chain validation), certificate/, l10n_it_edi
#                       (PKCS#7 via private OpenSSL APIs) and enterprise
#                       l10n_nl_reports. Removing it is a project, not a bump.
#   reportlab (5.x)     major; PDF output needs visual comparison
# Looks stale (last release 2022) and looks like it duplicates `cryptography`.
# It does neither — it is a declarative ASN.1 schema library, which cryptography
# deliberately is not, and all three consumers need exactly that:
#   tools/pdf/signature.py builds CMS SignedData around a digest computed over a
#     discontiguous PDF ByteRange (the two spans either side of the /Contents
#     placeholder) and sets a CMSAlgorithmProtection attribute. cryptography's
#     PKCS7SignatureBuilder only offers set_data(content) — it hashes the content
#     itself, so a precomputed byte-range digest cannot be expressed — and
#     PKCS7Options has no custom signed attributes.
#   l10n_eg_edi_eta uses asn1crypto.tsp (ESSCertIDv2, signing_certificate_v2);
#     cryptography ships no RFC 3161/5035 support at all.
#   auth_passkey's vendored webauthn declares Android Key attestation schemas by
#     subclassing asn1crypto.core.Sequence/SetOf/Enumerated.
# 1.5.1 IS the latest release. Do not swap it for cryptography.
